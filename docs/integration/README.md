# Head Bash Arena — інтеграція з Telegram-ботом

Для розробника бота (і його AI-агента: див. [`AGENTS.md`](AGENTS.md)). Тека самодостатня: її можна скопіювати в репозиторій бота.

**Що це дає:** у чаті хтось пише `/duel` → бот публікує кнопку «🎮 Грати» → двоє, хто натиснув, грають онлайн-матч у Telegram Mini App → бот пише в чат, хто переміг.

|---|---|

## 1. Як це влаштовано

```
 чат ── /duel ──▶ бот ── POST /lobbies ──────────────▶ ігровий сервер
                   │  ◀── code, miniAppUrl ───────────      (Cloudflare)
 чат ◀── кнопка-посилання miniAppUrl                          ▲
 гравці ── натискають ──▶ Mini App (гра) ── WebSocket ────────┘
                   бот ── GET /events?after=… (раз на 3–5 с) ──▶ хто зайшов, хто переміг
```

- **Бот не бере участі в самому матчі.** Він створює лобі й читає події. Гра й сервер спілкуються напряму, тож бот на домашньому сервері ніяк не впливає на затримку.
- **Бот сам опитує сервер** (`GET /events`). Публічна адреса, вебхуки й відкриті порти не потрібні, усе працює за NAT.
- **Налаштування матчу (арена, очки, час) обирає хост у грі.** Бот налаштувань не передає.
- **Лобі відкрите для будь-кого, хто має посилання.** Перші двоє займають місця, третій бачить «кімната заповнена».
- **Токен бота нам не потрібен.** Гравців з Telegram сервер перевіряє за підписом Telegram, і для цього достатньо числового id бота.

## 2. Що потрібно зробити один раз

1. **Отримати API-ключі** від власника гри (захищеним каналом, не в чат):
   - `staging` — для розробки й тестів: `https://head-bash-staging.headbash.workers.dev/api/v1`
   - `production` — для робочого бота: `https://head-bash.headbash.workers.dev/api/v1`

   Ключ зберігати там же, де токен бота (домашній сервер, змінна оточення, наприклад `HBA_API_KEY`).
2. **Зареєструвати Mini App** у [@BotFather](https://t.me/BotFather): `/newapp` → обрати бота → **Web App URL**: `https://shumykr.github.io/head-bash/` → коротка назва, наприклад `arena`.
3. **Передати власнику гри** (це не секрети):
   - числовий id бота: частина токена **до** двокрапки (`123456789:AA…` → `123456789`). Сам токен не передавати;
   - username бота (без `@`);
   - коротку назву Mini App з кроку 2.

   Без id бота гра працює, але гравці приходять без `tgUserId` під іменем, яке ввели в грі. Без username/назви `miniAppUrl` дорівнює `null`. Тоді посилання можна зібрати самому: `https://t.me/<bot>/<app>?startapp=<startParam>`.

## 3. Сценарій `/duel` крок за кроком

1. **Створити лобі:**
   ```js
   const lobby = await hba.createLobby({ meta: { chatId: ctx.chat.id }, idempotencyKey: `${ctx.chat.id}:${ctx.message.message_id}` });
   ```
   `meta` — будь-який JSON до 1 КБ, він повертається в кожній події цього лобі. `idempotencyKey` захищає від двох лобі, якщо Telegram повторить апдейт.
2. **Опублікувати кнопку-посилання** на `lobby.miniAppUrl`:
   ```js
   ctx.reply('⚔️ Виклик!', Markup.inlineKeyboard([Markup.button.url('🎮 Грати', lobby.miniAppUrl)]));
   ```
   У групах Telegram дозволяє відкривати Mini App лише через URL-кнопку (`web_app`-кнопки там заборонені). `lobby.webUrl` — те саме лобі у звичайному браузері, для тих, хто не в Telegram.
3. **Запам'ятати** `code → chatId, messageId` у своїй SQLite.
4. **Опитувати події**, поки є відкриті лобі: `hba.poll({...})` з `hba-client.mjs`. Курсор теж зберігати в SQLite. Тоді після перезапуску бот нічого не втратить і нічого не повторить.
5. **Реагувати на події:**

| Подія | Коли | `data` | Що зазвичай робить бот |
|---|---|---|---|
| `lobby.player_joined` | гравець зайшов | `{ player }` | «Олег у грі, чекаємо суперника» |
| `lobby.player_left` | гравець вийшов з лобі | `{ player }` | оновити список |
| `match.started` | обидва натиснули «готовий» | `{ players }` | «🔥 Олег vs Ігор» |
| `match.finished` | матч завершено | `{ winner, scores, reason, players }` | написати результат |
| `lobby.closed` | лобі закрито назавжди | `{ reason }` | прибрати кнопку, забути лобі |

`player` = `{ slot, name, tgUserId? }`. `slot` 0 — хост (той, хто зайшов першим), 1 — другий гравець. `scores` — `[очки slot 0, очки slot 1]`.

`reason` у `match.finished`:
- `score` — зіграли до кінця;
- `forfeit` — хтось здався або не повернувся за 15 с, переміг інший;
- `desync` — ігри розійшлися, матч не зараховано;
- `aborted` — обидва відключились, не зараховано.

`reason` у `lobby.closed`:
- `expired` — ніхто не зайшов за `ttlSec` (типово 10 хв);
- `cancelled` — бот скасував;
- `empty` — усі вийшли (через ~2 хв після останнього).

**Реванш:** після `match.finished` лобі повертається в `waiting`, і ті самі гравці можуть зіграти ще. Кожен матч дає свою пару `match.started` / `match.finished`. Лобі закривається, лише коли всі з нього вийшли.

## 4. Правила, на які варто зважати

- **Невідомі поля й типи подій ігнорувати.** У межах `v1` вони лише додаються (див. `CHANGELOG.md`).
- **Помилки:** `{ "error": { "code", "message" } }`. Розгалужуватися за `code` (таблиця в `examples/curl.md`).
- **Опитування:** раз на 3–5 с і лише поки є відкриті лобі. Події зберігаються 24 год: якщо бот лежав довше, найстаріші втратяться, тоді стан лобі можна дізнатися через `GET /lobbies/{code}`.
- **Дублікати:** `id` подій лише зростають. Не обробляти подію з `id ≤` уже обробленого.
- **Ключ:** лише на сервері бота, ніколи в коді Mini App, у Vercel-функціях чи в чаті. Staging і production мають різні ключі. Якщо ключ витік, написати власнику гри, щоб замінив.
- **Скасування** (`POST /lobbies/{code}/cancel`) можливе, лише поки матч не почався. Гравців, які вже зайшли, гра поверне в меню.

## 5. Перевірка без Telegram

1. `curl` зі [`examples/curl.md`](examples/curl.md) проти staging: створити лобі.
2. Відкрити `webUrl` у двох вкладках браузера (або на двох пристроях), в обох натиснути «готовий». Щоб здатися, у матчі є кнопка ⚑.
3. Подивитися, як у `GET /events` з'являються `player_joined ×2`, `match.started`, `match.finished`.

Через Telegram так само, лише кнопка в тестовому чаті. Mini App можна відкрити і в Telegram Desktop.
