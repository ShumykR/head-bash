# План: онлайн-режим і Telegram

Мета — двоє віддалених гравців грають один матч через інтернет. Та сама гра відкривається:

- **у звичайному браузері** (GitHub Pages, як зараз) — лобі за посиланням/кодом;
- **у Telegram** як Mini App — лобі запускається командою бота в чаті.

Обидва входи — **одна кодова база, одна збірка, один ігровий сервер**. Гравець із браузера й гравець із Telegram можуть грати разом.

**Telegram-бота пише й підтримує окремий розробник** (зі своїм кодом, стеком, хостингом і, ймовірно, своїм агентом). Тому з нашого боку інтеграція — це **публічний, задокументований, версіонований контракт** (HTTP API + журнал подій + формат посилань), а не код бота в цьому репозиторії. Див. розділ 3.

## 1. Ключові рішення

| Питання | Рішення | Чому |
|---|---|---|
| Мережева модель | **Детермінований lockstep із затримкою вводу** | `Game` уже детермінований: фіксований крок 60 Гц, власний seed-ГПВЧ (`game.rand()`), рендер відокремлений. Перевірено: два прогони 7200 кроків із тим самим seed і вводом дають побітово однаковий стан. Вхід — 1 байт на тік (напрямок + дія). Рендер не треба переписувати під знімки стану. |
| Сервер | **Cloudflare Workers + Durable Objects** (TypeScript) | Одна кімната = один Durable Object, що тримає два WebSocket. Безкоштовно, без картки, `wss://` і TLS з коробки на `*.workers.dev`, вузол поруч із гравцями (Варшава/Франкфурт). Мова та сама, що в грі, — спільні типи протоколу. |
| Фронтенд | **Лишається на GitHub Pages** | Mini App — це просто HTTPS-адреса; адреса Pages підходить. |
| Telegram у грі | **Адаптер платформи, не форк** | Форк розійдеться з основною грою, а lockstep вимагає побітово однакової симуляції в обох клієнтів. Різниця між платформами — вхід, авторизація, «поділитися», повноекранний режим. |
| Межа з ботом | **Integration API v1 (лобі + журнал подій для опитування, вебхуки — опція) + документація для людини й агента** | Розробник бота не чіпає код гри й сервера, працює у своєму стеку. Контракт описано машиночитно (OpenAPI), з прикладами й пісочницею. |
| Авторизація гравців Telegram | **Перевірка `initData` за підписом Ed25519 (third-party validation)** | Нашому серверу потрібен лише публічний `bot_id`, **токен бота лишається тільки в його розробника**. |
| Запасний бекенд | Oracle Cloud Always Free (VM, Франкфурт) | Якщо знадобиться серверна перевірка матчу повною симуляцією (у Worker не вистачить CPU). |

### Що свідомо НЕ робимо зараз

- **Rollback (GGPO).** Кращі відчуття, але потребує збереження/відновлення всього світу Planck і стану `Game`. Можна додати пізніше поверх lockstep.
- **Сервер рахує гру й розсилає стан.** Рендер читає живі об'єкти `Game` — довелося б переробити весь `src/render`.
- **Рейтинг, таблиці лідерів, історія матчів у нас.** Бот отримує результати подією `match.finished` і може вести це сам.
- **Серверна перевірка результату симуляцією.** Сервер вірить звітам клієнтів, але звіряє хеші обох; розбіжність = матч не зараховано.

## 3. Інтеграційний контракт (для розробника бота)

Принципи, щоб іншій людині й її агенту було зручно:

- **Одне джерело правди — `docs/integration/openapi.yaml`.** Агент може згенерувати клієнт будь-якою мовою; людина — відкрити в Swagger UI / Redoc.
- **Версія в шляху (`/api/v1`).** Лише додавання полів без зміни мажорної версії; ламаючі зміни — `/api/v2` з періодом підтримки обох. `CHANGELOG` у `docs/integration/`.
- **Кожен ендпоінт і подія мають готовий приклад** (curl + JSON запиту й відповіді) у `docs/integration/examples/`.
- **Пісочниця**: окреме staging-середовище з тестовим ключем, де можна створювати лобі й читати події, не чекаючи наших релізів.
- **Мок-сервер** (`npx @stoplight/prism-cli mock docs/integration/openapi.yaml` або наш `server` у `wrangler dev`) — розробка бота без мережі.
- **Однаковий формат помилок**: `{ "error": { "code": "lobby_not_found", "message": "…" } }`, стабільні `code` для гілок у коді бота.
- **Ідемпотентність**: `Idempotency-Key` на створенні лобі (бот може безпечно повторити запит).
- **Файл для агентів** `docs/integration/AGENTS.md`: коротко що є, де OpenAPI, як отримати ключ, як опитувати події, типові сценарії по кроках, чого не робити.

### 3.0. Що відомо про бота (від його розробника)

- Node.js + **Telegraf**, SQLite; ШІ-відповіді через Anthropic API.
- Бот працює на **домашньому сервері в Docker** (docker compose). Токен бота й ключ ШІ лежать лише там.
- Веб-частина (HTML-ігри, рекорди, «хто грає зараз») — **Vercel** (serverless + Redis) з окремим секретом.

Звідси вимоги до контракту:
- **Домашній сервер може бути недоступний з інтернету** (NAT, Telegraf у режимі long polling). Тому основний спосіб отримувати події — **бот сам опитує наш API** (розділ 3.2), а вебхуки — необов'язкова опція.
- **Токен бота нам не передається**: гравців перевіряємо за `bot_id` (розділ 3.3). Наш API-ключ зберігається на домашньому сервері поруч із токеном.
- Приклади коду — **лише JavaScript (Node.js, без залежностей, `fetch` + `node:crypto`)** і фрагмент для Telegraf.

Рішення власника гри: **хост керує всіма налаштуваннями в грі** (бот налаштувань не передає), **лише запрошення** (без публічного пошуку), **лобі в чаті відкрите для будь-кого**, хто натисне першим.

### 3.1. HTTP API (бот → наш сервер)

Автентифікація: `Authorization: Bearer <integration_api_key>` (видаємо ми, окремо для staging і production).

| Метод | Шлях | Призначення |
|---|---|---|
| `POST` | `/api/v1/lobbies` | Створити лобі. Тіло (усе необов'язкове): `meta` — довільний JSON до 1 КБ, який повертаємо в кожній події (напр. `{ "chatId": …, "messageId": … }`); `ttlSec` — скільки чекати гравців (типово 600). Заголовок `Idempotency-Key` — безпечний повтор. Відповідь: `code`, `startParam`, `miniAppUrl`, `webUrl`, `expiresAt`. |
| `GET` | `/api/v1/lobbies/{code}` | Стан: `status` (`waiting` / `playing` / `finished` / `expired` / `cancelled`), гравці (`name`, `tgUserId?`), рахунок, `result?`, `meta`. |
| `POST` | `/api/v1/lobbies/{code}/cancel` | Скасувати лобі, поки матч не почався. |
| `GET` | `/api/v1/events?after=<cursor>` | Події лобі цього бота після курсора (розділ 3.2). |
| `GET` | `/api/v1/health` | Доступність і версія API. |

`miniAppUrl` = `https://t.me/<botUsername>/<appShortName>?startapp=<startParam>` (з налаштувань інтеграції). У групах інлайн-кнопки `web_app` заборонені — бот шле кнопку-**посилання** (`Markup.button.url` у Telegraf).

Після матчу лобі повертається в стан очікування: ті самі двоє можуть зіграти реванш у грі, кожен матч — окрема подія `match.finished`.

### 3.2. Події: опитування (основний спосіб) або вебхук (опція)

Події однакові для обох способів:

| Подія | Коли | Ключові поля |
|---|---|---|
| `lobby.player_joined` | гравець зайшов у лобі | `code`, `player` (`slot`, `name`, `tgUserId?`), `meta` |
| `lobby.player_left` | вийшов до старту | те саме |
| `match.started` | хост запустив матч (обидва готові) | `code`, `players`, `meta` |
| `match.finished` | матч завершено | `code`, `winner` (`slot`, `name`, `tgUserId?`) або `null`, `scores`, `reason` (`score` / `forfeit` / `desync` / `aborted`), `meta` |
| `lobby.closed` | лобі закрито: прострочене, скасоване або всі вийшли | `code`, `reason` (`expired` / `cancelled` / `empty`), `meta` |

Кожна подія: `{ id, type, at, code, data, meta }`; `id` зростає — за ним бот відкидає дублікати.

**Опитування (типово).** `GET /api/v1/events?after=<cursor>` → `{ events: [...], cursor }`. Бот запам'ятовує `cursor` (у своїй SQLite) і питає раз на 3–5 с — **лише поки в нього є відкриті лобі**, тож у тиші запитів нуль. Події зберігаються 24 год. Працює за NAT, не потребує публічної адреси й нових секретів.

**Вебхук (за бажанням).** Якщо в бота з'явиться публічний HTTPS-endpoint (наприклад, функція на Vercel), задаємо `webhookUrl`, і події приходять `POST`-ом: заголовки `X-HBA-Event`, `X-HBA-Delivery` (= `id` події), `X-HBA-Timestamp`, `X-HBA-Signature: sha256=<HMAC-SHA256(secret, timestamp + "." + body)>`; повтори до 24 год, поки не буде `2xx`. Опитування при цьому теж працює — як запасний шлях.

Події кожного раунду (`match.round_finished` з проміжним рахунком, щоб бот оновлював повідомлення «2:1» під час гри) **не робимо**: зайвий функціонал. Якщо знадобиться — додається в `v1` без поломок (нова подія, старий код її просто ігнорує).

### 3.3. Mini App і ідентичність гравця

- Розробник бота реєструє Mini App у BotFather (`/newapp`) на адресу Pages гри; гра сама визначає, що відкрита в Telegram.
- Гра читає `Telegram.WebApp.initDataUnsafe.start_param` = `startParam` → одразу відкриває лобі.
- Формат `startParam`: `l_<code>` (лише `[A-Za-z0-9_-]`, до 64 символів — обмеження Telegram).
- Гра передає сирий `initData` на сервер у `hello`; сервер перевіряє підпис `signature` за публічним ключем Telegram і `bot_id` інтеграції (third-party validation, Bot API 8.0+) і бере звідти `tgUserId` та ім'я. Застарілий `auth_date` (> 24 год) — відмова. **Токен бота для цього не потрібен.**
- Ті самі лобі працюють і без Telegram: `webUrl` = `https://<pages>/?room=<code>` (гість без Telegram — анонімне ім'я).

### 3.4. Середовища й налаштування інтеграції

| Середовище | API | Гра | Для чого |
|---|---|---|---|
| `staging` | `https://head-bash-staging.<acc>.workers.dev/api/v1` | збірка з `VITE_SERVER_URL` на staging | розробка бота, тести |
| `production` | `https://head-bash.<acc>.workers.dev/api/v1` | GitHub Pages `main` | живі чати |

Налаштування інтеграції (одна на бота, в сховищі Durable Object): `apiKey` (лише хеш), `botId`, `botUsername`, `appShortName`, `webhookUrl?`, `webhookSecret?`. Створюється скриптом `server/scripts/integration.ts`; кабінет не потрібен.

**Вартість опитування для нас:** запит раз на 4 с, поки є відкрите лобі, — це сотні запитів на день, а не десятки тисяч. Ліміт безкоштовного плану (100k/добу) лишається для матчів.

### Затримка: бот поза ігровим циклом

- Під час матчу трафік іде лише гравець ↔ Room по WebSocket. Бот у цьому шляху не бере участі.
- Вебхуки шлються асинхронно (`ctx.waitUntil` / черга): кімната не чекає відповіді бота.
- `initData` перевіряється один раз у `hello` (Ed25519 через WebCrypto, < 1 мс).
- **Розміщення кімнати.** Durable Object створюється поруч із тим, хто першим до нього звернувся. Тому `POST /api/v1/lobbies` лише резервує код (у сховищі інтеграції), а DO кімнати створюється, коли підключається перший гравець. Інакше кімната, створена ботом із сервера в США, жила б у США. Додатково задаємо `locationHint: "eeur"`.

`docs/integration/` — самодостатня: її можна скопіювати в репозиторій бота або дати агенту як контекст без решти нашого коду.

## 5. Протокол гри (`src/net/protocol.ts`)

Внутрішній протокол клієнт ↔ сервер; розробнику бота він не потрібен. JSON на етапі лобі, компактні повідомлення під час матчу. Кожне повідомлення має `t` (тип).

**Клієнт → сервер**

| t | Поля | Коли |
|---|---|---|
| `hello` | `build` (sha), `proto`, `name`, `auth?` (Telegram initData) | одразу після підключення |
| `pick` | `car` | вибір авто в лобі |
| `config` | `map`, `target`, `roundTime`, `randomCars` | лише хост (якщо лобі створене без `config`) |
| `ready` | — | готовий до старту |
| `in` | `k` (тік), `b` (біти: ліво/право/дія) | лише коли ввід змінився + раз на 0.5 с «без змін» |
| `hash` | `k`, `h` | кожні 60 тіків |
| `result` | `winner`, `scores` | кінець матчу |
| `ping` | `ts` | раз на 2 с |

**Сервер → клієнт**

| t | Поля | Коли |
|---|---|---|
| `welcome` | `slot` (0/1), `code`, `peer?` | після `hello` |
| `lobby` | стан обох гравців, конфіг | при кожній зміні |
| `start` | `seed`, `cars`, `config`, `delay` (тіків) | обидва `ready` |
| `in` | `p`, `k`, `b` | пересилання вводу суперника |
| `desync` | `k` | хеші за тік `k` не збіглися |
| `peerLeft` / `peerBack` | — | обрив / повернення суперника |
| `end` | `winner`, `reason` (`score` / `forfeit` / `desync`) | кінець матчу |
| `pong` | `ts` | відповідь на ping |
| `reject` | `reason` (`version`, `full`, `notFound`, `auth`) | відмова |

Сервер не пускає в кімнату клієнти з різними `build` → клієнт пропонує перезавантажитися (важливо через Service Worker і кеш WebView у Telegram).

## 6. Мережевий код (lockstep)

1. Після `start` обидва клієнти створюють `Game` з однаковим `seed`, авто й конфігом.
2. Ввід, зібраний на кадрі, призначається тіку `current + delay` (`delay` ≈ RTT/2 / 16.7 мс + 2, у межах 3–8). Він одразу йде на сервер і в локальний буфер.
3. Тік `k` виконується (`game.step()`) лише коли відомий ввід **обох** гравців на `k`. Бракує вводу суперника → чекаємо (рендер продовжує малювати, гра «підвисає»). Повідомлення шлються лише при зміні вводу, тож «немає нових даних до тіку N» означає «ввід той самий».
4. Темп: кроки викликаються з `main.ts` напряму, без `FixedStepper` на реальному часі; slow-mo лишається суто темпом відтворення (обидва клієнти рахують його з однакового стану — на результат не впливає).
5. Кожні 60 тіків — хеш стану на сервер. Розбіжність → `desync` → матч зупиняється й не зараховується (на першому етапі; відновлення стану — пізніше).
6. Обрив: суперник зник → пауза з таймером 15 с → `peerBack` (кімната переслала пропущений ввід) або технічна поразка.

### Етап 0. Детермінізм між рушіями — ✅ готово

Ризик: iOS (WebKit/JSC) і Android/десктоп (Chromium/V8) можуть по-різному округлювати `Math.sin/cos/tan/atan2/exp/log/pow`. Planck ними користується → гра розійдеться за кілька секунд.

- [x] `scripts/detcheck.mjs` (`npm run detcheck`): сценарний матч `src/net/detrun.ts` (фіксований seed + записаний ввід, випадкові авто й арени) → хеш стану кожні 60 тіків у Node, Chromium, WebKit, Firefox; порівняння.
- [x] Прибрано `Math.random` із симуляції (`game.ts` — виліт водія, `ragdoll.ts` — обертання голови) + тест, що симуляція не викликає `Math.random`.
- [x] **Результат без змін:** Node і Chromium (обидва V8, різні версії) розходяться **на першому кроці** — `Math.atan2(sin(-0.12), cos(-0.12))` дає `-0.12000000000000001` проти `-0.12`.
- [x] `src/net/detmath.ts`: `sin/cos/tan/atan2/exp/pow/hypot` замінені чистими JS-портами fdlibm (`@stdlib/math-base-special-*`) на глобальному `Math`. Ставиться першим імпортом (`src/net/detmath-install.ts`) у `main.ts` і в `tests/setup.ts` — модулі авто й арен рахують геометрію ще під час завантаження.
- [x] Хеш стану `src/net/hash.ts` (+ поелементний для діагностики) + тести `tests/net.test.ts`.
- [x] CI: job `determinism` у `deploy.yml` (3 хв гри, 4 рушії, `--strict`).
- [x] Усі 2242 наявні тести проходять з новою математикою; смоук у браузері без помилок. Симуляція 10 хв займає ~5 с — нова математика не помітна за швидкодією.

**Готово, коли:** 10 хв матчу з випадковими авто й аренами дають однакові хеші в Node, Chromium і WebKit. ✅ Виконано: seed 42 і 7, по 600 хешів, Node = Chromium = WebKit = Firefox.
